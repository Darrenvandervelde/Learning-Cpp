# Module 01 Formal Assessment

## 1. Assessment conditions

Complete the assessment independently after the laboratories and exercises. You may consult official language and compiler documentation. You must disclose external code used and be able to explain every submitted line.

## 2. Assessment components

| Component | Points |
|---|---:|
| A. Technical understanding | 25 |
| B. Code analysis and correctness | 30 |
| C. Memory safety and C++ practices | 20 |
| D. Engineering reasoning | 15 |
| E. Code quality and communication | 10 |
| **Total** | **100** |

## 3. Part A: Technical understanding

Answer in your own words.

1. Describe the major stages between a C++ source file and program execution.
2. Explain the responsibilities of the compiler and linker.
3. Define an object file and an executable.
4. Explain what the C++20 compiler option requests.
5. Explain why a successful build is not a proof of correctness.

## 4. Part B: Code analysis and correctness

The assessor will provide two short programs. One will contain a syntax defect. The other will contain a missing external definition.

For each program:

1. Identify the relevant source or build stage.
2. Predict the diagnostic category.
3. Explain the underlying cause.
4. Propose the smallest appropriate correction.

Then build your independent player status program.

## 5. Part C: Memory safety and C++ practices

Demonstrate a valid hosted program structure, appropriate use of standard output and a warning enabled build. Explain why no application managed dynamic allocation is needed for this task.

## 6. Part D: Engineering reasoning

Explain how you would investigate a failed build without randomly changing code. Your process must include reading the first useful diagnostic, checking the file and line, identifying the stage and rebuilding after a focused correction.

## 7. Part E: Code quality and communication

Submit readable source, exact build commands, compiler version, actual output and a concise technical explanation. The assessor must be able to reproduce the build from the submitted instructions.

## 8. Mandatory pass conditions

A score of at least 80 is required. The independent program must build and meet its requirements. The student must explain the code and the build process. An unresolved critical defect or inability to explain the work blocks progression.

## 9. Reassessment

A student who does not pass receives feedback identifying the specific learning outcomes not demonstrated. The reassessment uses new code and changed questions. The pass threshold does not change.
